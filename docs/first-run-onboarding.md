# 首次使用引导

## 目标

帮助新用户选定界面、添加首个配置并完成首次 VPN 授权；熟悉应用的用户可以直接进入原有主界面。界面推荐项为 Chimera（Compose），CMFA 风格仍可选择，并可在设置中切换。

## 启动规则

- 仅在首次安装且尚未完成引导时自动打开引导。通过应用首次安装时间与最近更新时间区分新安装和应用升级，升级用户不会被强制打断。
- 欢迎页的“我已熟悉，跳过引导”会直接打开当前默认主界面，不增加引导专用空状态。新安装未改过偏好时，默认界面为 Chimera。
- 记录当前引导步骤。应用被系统回收后，新用户从上次完成的步骤继续。
- 引导完成后可从 Chimera 界面的设置页重新打开；CMFA 界面可从帮助页重新打开。
- CMFA 帮助页的视觉参照固定为 `ref/ClashMetaForAndroid` 修订 `3cc102aab3f251ef460a3b6e2835b6c1eb581e73`；引导入口沿用该页已有的可点击列表样式。

## 视觉复核

- 在 Android API 36、x86_64、1080×1920 模拟器上对照参考应用和 Chimera 的帮助页。参考页原有工具栏、免责声明、Document / Sources 标题和链接顺序保持一致；新入口放在免责声明之后、Document 标题之前，沿用现有列表的左侧留白、标题和摘要排版。原有内容仅因插入新行而向下移动。
- 同一模拟器检查引导欢迎页、界面选择页和配置导入页：Chimera 推荐项默认选中；两张界面预览均可辨认；选择页底部按钮避开系统导航栏；状态栏图标在浅色背景下可见。
- 参考源码修订：`3cc102aab3f251ef460a3b6e2835b6c1eb581e73`。本次变更未尝试重绘或改动 CMFA 帮助页其他组件。

## 流程

1. **欢迎**：介绍接下来会选择界面、添加配置并尝试连接；提供开始和熟悉用户跳过入口。
2. **选择界面**：展示 Chimera 与 CMFA 两种界面的预览和说明。Chimera 默认选中并标为推荐。确认后保存偏好；设置页仍可切换。
3. **添加配置**：提供从文件导入、添加订阅链接、扫描二维码三个入口。二维码读取到链接后先填入订阅链接输入框，用户确认后再下载。文件、链接均通过现有后端导入和配置校验；成功后显示配置名称并继续。
4. **首次连接**：说明 Android VPN 授权用途。只有用户点击“连接并授权”后才调用现有 VPN 启动流程并显示系统授权提示。拒绝授权或启动失败时留在本页，可重试；仅当后端状态变为运行中才显示完成。
5. **完成**：后端状态仍为运行中时显示连接成功，可展开常用操作提示，再进入主界面。若服务停止，完成步骤会返回连接页；从系统恢复的完成步骤也会先核对运行状态。

## 订阅链接失败说明

引导根据后端和下载器实际返回的信息分类，不将所有失败都归为“链接错误”：

- HTTP 401/403：服务器拒绝访问；显示状态码并建议检查订阅权限和链接。
- HTTP 404/410：服务器找不到订阅；提示链接可能过期或地址不完整。
- HTTP 5xx：服务器返回服务错误；提示检查服务状态或稍后重试。
- 超时、DNS、连接失败：归为网络或服务器连接问题，并明确仅凭这些错误不能断定链接无效。
- TLS、重定向过多、下载超限、空响应、HTML 页面、配置解析失败和本地文件读取失败：分别给出对应原因和处理建议。
- 不展示底层异常原文，避免把订阅 URL 中的令牌或查询参数泄露到引导页面。订阅 URL 只保留在当前输入状态，不写入引导偏好。

## 实现边界

- 复用 `ChimeraBackend` 的文件/远程配置导入、配置校验和 VPN 启动接口；二维码扫描沿用现有 Quickie 扫描器。
- 引导不自动启动 VPN，不改变 Rust、UniFFI 接口或两套主界面的配置和运行状态共享方式。
- 配置导入进行中时，系统返回和页头返回会被暂时拦截，避免后台导入完成后意外跳转。
- 现有用户升级后保持原有启动路径。跳过引导进入现有主界面及其原有空状态和配置入口。
